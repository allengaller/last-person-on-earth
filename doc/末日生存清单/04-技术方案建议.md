# 04 · 技术方案建议

> 工程指导文档：单独起 repo 时按此实现。核心策略：**数据模型驱动**——先定实体与关系，界面从数据推导。开发工具建议 Cursor / Trae（Mac 本地 AI Agent 流）。

---

## 1. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 框架 | **Vite + Vue 3 + `<script setup>`** | 转小程序首选 uni-app（Vue 生态无缝）；单文件组件对 Cursor 生成友好 |
| 状态 | Pinia | 拥有清单/准备度/技能解锁集中管理，逻辑与视图分离，AI 可单测 |
| 样式 | 原生 CSS 变量 + scoped style | Token 全局一份（03 文档），不引入 Tailwind（减少 AI 生成噪声） |
| 动效 | 纯 CSS（conic-gradient / clip-path / steps） | 零动画库，Glitch 与雷达都是两层伪元素的事 |
| 持久化 | localStorage（单一 key `doomsday-state-v1`） | 无后端；导出/导入 JSON 即云端备份的前身 |
| 路由 | vue-router（hash 模式） | hash 模式静态托管零配置 |
| 部署 | GitHub Pages / Vercel 静态托管 | v0.2 上线 |

**明确不做（v0.1）**：后端、登录、云同步、i18n、PWA、测试框架（用 Vite 项目的最小化配置起步）。


```js
// src/stores/user.js —— 用户状态（唯一可变数据，localStorage 持久化）
state: () => ({
  owned: {},          // { "fw-01": true, … }  勾选即收集
  practiced: {},      // { "water-2": true }   技能练习标记
  unlocked: {},       // 由 getter 推导，不落库
  createdAt: ts,
})
```

**要点**：静态内容（items/scenarios/skills）与用户状态（stores/user）彻底分离——前者是"数据库"，后者是"存档"，界面全部由二者 join 推导，无散落的局部 state。

## 3. 核心算法

### 3.1 准备度评分

```js
const CATEGORY_WEIGHTS = {
  "food-water": 0.25, "medical": 0.25, "gear-tools": 0.2,
  "power-comm": 0.2, "docs": 0.1,
};

// 总准备度 = 分类维度 70% + 技能维度 30%
total = sum(w * ownedRate(cat)) * 0.7 + practicedRate(skills) * 0.3;
ownedRate(cat) = ownedItems(cat) / totalItems(cat);
// 展示为 0-100 整数；六维雷达数据 = 5 分类 ownedRate + 技能 practicedRate
```

段位映射：`0-20 纯脆皮 / 21-40 普通路人 / 41-60 有备而来 / 61-80 老练幸存者 / 81-100 废土传说`（纯前端查表）。

### 3.2 技能解锁推导

```js
// unlocked = 纯 getter：不存储，状态变化自动重算
isUnlocked(skill) =
  countOwned(skill.requireItems) >= skill.requireItemsCount
  && (!skill.requirePractice || practiced[skill.id]);
```

### 3.3 场景准备度

```js
scenarioRate(sc) = countOwned(sc.recommended 全量) / count(recommended 全量);
// 场景详情按 P1/P2/P3 分组显示缺口："该场景还缺 3 件 P1 物资"
```

## 4. 持久化与数据管理

- 读写时机：状态变更即写（`watch(state, persist, { deep: true })`），启动时读入并 try/catch 容错（脏数据 → 重置为空状态并提示）
- 导出/导入（v0.2）：`JSON.stringify(state)` 下载为 `doomsday-backup.json`；导入做字段校验（白名单 key + 类型检查）
- 版本号：state 内嵌 `schemaVersion: 1`，未来迁移在此分支

## 5. 动效实现要点

| 动效 | 实现 |
|------|------|
| 雷达扫描屏 | 全屏组件，`conic-gradient` 扇形 + `animation: rotate 1.2s linear`；打字机用 `setInterval` 逐字追加；`setTimeout 1200ms` 自动进入首页，可点击跳过 |
| Glitch 转场 | `<router-view>` 外层容器两伪元素，切换时加 class 触发两帧 `clip-path: inset()` 错位动画 + `filter: drop-shadow(2px 0 var(--alert)) drop-shadow(-2px 0 var(--rad))`；300ms 后移除 class |
| 印章勾选 | checkbox 自绘：checked 时"√"元素以 `animation: stamp .25s steps(2)` 落定 |
| reduced-motion | 全部动画包在 `@media (prefers-reduced-motion: no-preference)` 内 |

## 8. 转小程序路线（v0.3 备选）

| 路线 | 做法 | 适用 |
|------|------|------|
| A. WebView 壳 | 小程序 web-view 直接加载已部署站点 | 最快验证，1 天级 |
| B. uni-app 重写 | 组件层重写为 uni-app，data/stores 原样复用 | 长期方案，Vue 代码复用 ~70% |

推荐先 A 后 B：先用 WebView 壳验证小程序内体验，数据模型驱动的架构保证了重写时"内容层零改动"。

## 9. 验收清单（v0.1）

1. `npm run dev` 起本地环境；`npm run build` 产物可静态托管
2. 数据完整性：物资 ≥ 50 条、场景 3 个、推荐组合引用的物资 id 全部存在（写个 10 行校验脚本跑一次）
3. 评分算法：勾选 fw-01 后准备度、分类完成度、城市避难场景准备度同步变化且数值正确
4. 状态持久化：勾选 → 刷新 → 状态保持；清 localStorage → 回到空清单
5. 三大动效齐备：雷达屏（1.2s 可跳过）、Glitch 转场（≤300ms）、印章勾选（≤250ms）
6. `prefers-reduced-motion` 下无任何循环动画
7. 375px 宽度走查：无横向滚动、TabBar 避让安全区、触控目标 ≥ 44px
8. 合规文案到位：医疗分类页头提示、md-04/md-10 条目提示、关于页免责声明
